## Architecture

This is a **Rails 7.2 app** for CDCH (Centro de Desarrollo Científico y Humanístico), a Venezuelan university research center. It serves two audiences:

1. **Public landing pages** (`PagesController`, `app/views/pages/`) — unauthenticated, shows institutional info, events, publications, etc.
2. **Dashboard** (`DashboardController` + `app/controllers/dashboard/`) — authenticated admin area for managing content.

### Authentication & Authorization

- **Devise** handles authentication. All controllers require login by default (`before_action :authenticate_user!` in `ApplicationController`). `PagesController` skips this.
- **CanCanCan** handles authorization via `app/models/ability.rb`. The `Ability` class derives permissions from `user.role` (delegated from `JobTitle`) and `UserPermission` records.

**Role hierarchy** (defined as enum on `JobTitle`):
- `Regular` → read-only for own department
- `Coordinador` → read department
- `Administrador` → manage own department
- `JefeDepartamento` → read own department (except DTIC department head who gets full access)
- `Superadmin` → full access (Director/Subdirector job titles are read-only even with Superadmin role)

**Fine-grained permissions** are stored in `user_permissions` table as tokens like `"Call:read"` or `"Publication:create"`. Resources scoped by `department_id` where available; `InstitutionLeadership` is an exception (not scoped by department).

### Key Models

- **`User`** — belongs to `Department` and `JobTitle`; role is delegated from `JobTitle#role`
- **`JobTitle`** — holds the role enum; many job titles can map to the same role (e.g., multiple "Director" records)
- **`Department`** — organizational units; `acronym` field used for routing (e.g., `"Dir"`, `"Subdir"`, `"DTIC"`)
- **`Institution`** — singleton record for the institution's info (always use `Institution.first`)
- **`InstitutionLeadership`** — historical record of directors/subdirectors; `role` enum: `director: 0, subdirector: 1`; validates no overlapping date periods per role using PostgreSQL `daterange`
- **`UserPermission`** — stores permission tokens `"Resource:action"` (resource from `RESOURCE_MAP`, action from `ACTION_MAP`)

### Dashboard Controllers

All under `app/controllers/dashboard/` and namespaced with `module: 'dashboard'` in routes. They use CanCanCan's `load_and_authorize_resource` pattern.

### Public Pages

`PagesController` actions map to views in `app/views/pages/`. URL slugs are in Spanish (e.g., `/direccion`, `/subdireccion`, `/galeria-autoridades`). Routing for departments uses the `acronym` field.

### Frontend

- **Bootstrap 5** + custom SCSS in `app/assets/scss/` based on SB Admin 2 theme
- **Importmap** (no Node/webpack) with **Stimulus** and **Turbo**
- **ActionText** (Trix editor) for rich text fields (e.g., `InstitutionLeadership#bio`)
- **Active Storage** for file uploads (user photos, institution logos, leadership photos, publication files)
- **will_paginate** for pagination
- **Font Awesome** for icons

### Localization

All UI strings are in Spanish. `config/locales/es.yml` contains ActiveRecord model/attribute translations, flash messages, enum labels, and date/time formats. Use `t()` helpers in views for any user-facing strings.

### Database

PostgreSQL. The app uses PostgreSQL-specific features:
- `daterange` overlap queries in `InstitutionLeadership`
- `COALESCE` and `Arel.sql` for custom ordering

### Special Conventions

- `Department#acronym` drives routing and business logic: `"Dir"` = Dirección, `"Subdir"` = Subdirección, `"DTIC"` = tech department with special admin privileges
- `InstitutionLeadership` ordered via `.ordered_for_gallery` scope: by role, then active first, then most recent
- Flash messages use i18n keys: `t("flash.actions.create.notice", model: ...)`
- Model schema comments are auto-generated by `annotaterb` at the top of each model file
